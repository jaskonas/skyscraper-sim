# Zones: Paint the Stack Implementation Plan (Plan 14)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the player split the tower into zones of shops, offices, hotel and homes in any order, rate how well each zone fits its floors, and show what the tower earns and how fast it pays for itself.

**Architecture:**
- The design's fixed four-percentage `useMix` becomes an ordered `stack` of bands. Every existing consumer still goes through `floorUses` / `useShares`, so they follow the new stack without changes.
- Fit and income are pure sim functions feeding a new `analysis.value`, a Value grade and two brief requirement kinds.
- The UI adds a stack-editor strip in the sidebar and a 🏷️ Zones 3D view that reuses Plan 13's ghosting.

**Tech Stack:** TypeScript 5.9, React 19, Zustand 5, three 0.186 / @react-three/fiber 9, Vitest 5 (jsdom, @react-three/test-renderer).

**Spec:** `docs/superpowers/specs/2026-10-29-zones-design.md`

## Global Constraints

- **Stack size:** 1–6 bands. Adjacent bands with the same use merge. Every band covers at least 1 floor after rounding (unless floors < bands).
- **Floor assignment:** a stack built by `stackFromMix(oldMix)` must give exactly the same `floorUses` as the old fixed-order code.
- **Floor numbers** in all player-facing text count from 1 (floor index 0 is "floor 1").
- **Fit depth:** 0.35 × min(width, depth) per slice, averaged over the band.

  | Use | 👍 | 😐 | otherwise |
  |---|---|---|---|
  | Offices | 9–18 m | 7–22 m | 👎 |
  | Hotel | 5–10 m | ≤ 13 m | 👎 |
  | Homes | 6–12 m | ≤ 15 m | 👎 |
  | Shops | ≥ 6 m | — | 👎 below 6 m |

- **Height:**
  - Shops not starting at index 0 get 😐 without an observation deck, 👍 with one.
  - Hotel or homes starting below index 5 get 😐.
- **Size:** a hotel band of fewer than 5 floors gets 😐.
- **Rating:** the worst factor wins, and ties go in order depth, height, size.
- **Base rent** ($/m²/yr): office 220, residential 200, hotel 240, retail 260.
- **Height premium** by floor index `i`:
  - homes and hotel: min(0.8, 0.01·i);
  - offices: min(0.3, 0.003·i);
  - shops: 0, except shops not at the street with an observation deck, which use the homes rule.
- **Fit multiplier:** 👍 1.0, 😐 0.8, 👎 0.55.
- **City market factor:**

  | City | Offices | Homes | Hotel | Shops |
  |---|---|---|---|---|
  | New York | 1.2 | 1.3 | 1.1 | 1.2 |
  | Tokyo | 1.15 | 0.95 | 1.0 | 1.1 |
  | Chicago | 1.0 | 1.0 | 1.0 | 1.0 |
  | Shanghai | 0.7 | 0.7 | 0.8 | 0.7 |

- **Payback** = cost.total / incomePerYear, rounded to 1 decimal.
- **Value grade:** ≤ 15 years A, ≤ 20 B, ≤ 26 C, ≤ 34 D, else F.
- **Labels and colours:**
  - Use labels: Shops 🛍️, Offices 🏢, Hotel 🛎️, Homes 🏠.
  - Use colours: shops `#f2a93b`, offices `#4a7fd4`, hotel `#9a5fd0`, homes `#4fae6a`.
  - All player-facing wording lives in `src/sim/catalog/zones.ts`.
  - Emoji in buttons go inside `<span aria-hidden="true">`.
- **Edits are undoable:** stack edits go through `dispatch`. A drag uses `coalesceKey: 'stack-drag'` plus `endCoalesce`, so one drag is one undo step.
- **Zones 3D view:** at most 10 extra draw calls; hidden while building; exclusive with forces and systems.
- **Machine is overloaded:** run Vitest with `--maxWorkers=2 --testTimeout=120000`, or file by file.

## Review Focus

1. **Stack from a design that lost floors** (60 floors, 6 bands, then floors set to 4): no band may get negative or NaN floors, `bandFloors` must still cover every floor exactly once, and the UI must not crash. → Task 1 test `bandFloors covers every floor once even with fewer floors than bands`.
2. **Dragging a boundary to the very edge:** the neighbour band must keep ≥ 1 floor, and the boundary must not cross it. → Task 1 test `moveBoundary clamps so both bands keep a floor`.
3. **Removing or moving a band so two same-use bands become neighbours:** they merge, and `selectedBand` must not point past the end of the stack. → Task 1 test `removeBand merges same-use neighbours`; Task 6 test `selection clamps after remove`.
4. **A design or brief patch that still carries `useMix`** (old exported JSON, a missed test patch): TypeScript must reject it. `normalizeDesign` gives a missing or empty `stack` the default `[{retail,10},{office,90}]` instead of crashing. → Task 2 test `normalizeDesign repairs a missing or empty stack`.
5. **Zero income** (every band 👎 on a tiny lot): payback must be `Infinity`, shown as "never", graded F, with no division error. → Task 4 test `payback is Infinity when income is zero`.

**Interfaces:**
- Produces:
  ```ts
  export interface UseBand { use: UseType; share: number }            // in types.ts
  export interface BandSpan { index: number; use: UseType; from: number; to: number } // from/to are floor indices, inclusive
  export const MAX_BANDS = 6;
  export function stackFromMix(mix: Record<UseType, number>): UseBand[]
  export function normalizeStack(stack: UseBand[]): UseBand[]          // drop share<=0, merge same-use neighbours, cap 6 (merge the extras into the 6th), shares rescaled to sum 100; empty → [{use:'office',share:100}]
  export function bandFloors(stack: UseBand[], floors: number): BandSpan[]
  export function moveBoundary(stack: UseBand[], floors: number, boundary: number, toFloor: number): UseBand[] // boundary k sits between band k and k+1; toFloor = first floor index of band k+1
  export function moveBand(stack: UseBand[], index: number, dir: -1 | 1): UseBand[]
  export function setBandUse(stack: UseBand[], index: number, use: UseType): UseBand[]
  export function splitBand(stack: UseBand[], index: number, use: UseType): UseBand[] // upper half gets `use`
  export function removeBand(stack: UseBand[], index: number): UseBand[] // gives its share to the band below (or above if it is the bottom); no-op on the last band
  ```
  Every edit helper returns `normalizeStack(...)`.
